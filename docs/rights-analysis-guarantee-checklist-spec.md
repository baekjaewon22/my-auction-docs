# 권리분석 보증서 — 2페이지 특이사항 체크표 스펙 (확정 초안)

작성일: 2026-08-28 · 상위 기획: [rights-analysis-guarantee-roadmap.md](./rights-analysis-guarantee-roadmap.md)

로드맵 "다음 시작점 #2·#3"(2페이지 체크표 항목·순서 확정 + 자동판정 가능 여부 매핑)의 결과물이다.
각 항목의 판정 근거는 실제 코드/규칙 데이터(`rights_certificate.py`, `special_situations.py`, `권리분석_규칙.json`, `기준표_소액임차인.json`)를 조사해 매핑했다.

## 판정 구분

- **auto** — 현재 파싱 데이터/규칙으로 자동 판정 가능
- **hybrid** — 자동 후보 신호는 있으나 담당자 확정 필요
- **manual** — 자동 판정 데이터가 없어 담당자 수동 체크

5상태: **이상없음(녹색) / 확인필요(주황) / 위험(빨강) / 미확인(회색) / 해당없음(N/A)**. 체크표에는 상태만 표시하고, `위험`·`확인필요` 항목만 상세 페이지로 전개한다.

집계: 총 **32개 항목** — auto **7** · hybrid **16** · manual **9**.

## 확정 결정 (2026-08-28)

1. **입력 확보** — 등기부·매각물건명세서·현황조사서는 업로드·OCR로 이미 파이프라인에 공급됨 → auto/hybrid 판정이 실제 동작(전제 충족).
2. **노출 범위** — 자동+혼합(23개)은 **본 체크표**, 수동(9개)은 **담당자 수동 체크 부록**으로 분리.
3. **상태 체계** — 4상태 + `해당없음(N/A)` 추가(총 5상태). 물건종별 무관 항목은 '이상없음'이 아닌 N/A로 표기.
4. **상품명** — '보증서' 명칭 유지, 유료화 전 약관·면책·명칭 재검토.

### 본표 / 수동 부록 배치

- **본 체크표(자동 판정, 23)**: 권리관계 9 · 임차·점유 6 · 물건 위험 4 · 입찰·비용 4
- **담당자 수동 체크 부록(9)**: 소유자와의 관계, 명도 난이도, 제시외 건물, 맹지/도로 접함, 경계 문제, 재개발·재건축, 부대비용, 매각불허가 사유, 입찰보증금 특례
- 아래 카테고리별 표는 전체 매핑 기준이며, 판정 열의 `manual`은 아래 '방향 변경'으로 재분류된다.

## 방향 변경 (2026-08-29) — 완전 자동화 · 대량 생산

- **수동 입력 폐기**: 대량 생산을 위해 담당자 수동 체크 없이 **100% 자동 생성**. 이전 '수동 부록 9'와 hybrid의 '담당자 확정' 전제 폐기.
- **미판정 처리**: 자동 판정 불가 항목은 사람에게 넘기지 않고 **`미확인`(물건종별 무관 시 `N/A`)로 자동 표기** + 보수적 면책 문구.
- **판정 방식 재정의**: (a) 규칙엔진 결정판정, (b) 파싱 신호, (c) **MD 지식베이스 기반 추론**(교재·사례·심사기준·특이사항 카탈로그 참조), (d) 불가 → 미확인.
- **참조 지식베이스**: `special-situations-master.yaml`, `review-standard.md`, `property-checklist.md`, `경매교재-초보자과정_정리.md`, `권리분석_규칙.json`, `기준표_소액임차인.json`, `권리분석_용어사전.json`, `qna/용어사전.md`, `qna/경매사례.md`.
- **⚠️ 리스크(무인 발급)**: 사람 검토 없는 자동 대량 발급은 로드맵의 '자동초안 → 담당자 검토·서명 후 발급' 전제와 상충. '보증서'라는 명칭으로 무인 발급 시 실손해 보전·오류 책임 노출 → 명칭·면책·`자동생성` 표기의 법적 재검토가 별도로 필요(유료화 전 필수).

## 완전자동 재매핑 결과 (2026-08-29)

지식베이스(`special-situations-master.yaml` 46개 카탈로그, `권리분석_규칙.json`, `기준표_소액임차인.json`, 교재·사례·심사기준)를 근거로 32개를 완전자동 기준 재매핑. 판정 방식: **규칙엔진 / 자동탐지(신호) / 지식베이스 추론 / 불가**. 이 절이 위 auto/hybrid/manual 분류를 대체한다.

방식 집계: 규칙엔진 8 · 자동탐지 10 · KB추론 11 · 불가 3.

### 3단계 현실

- **A. 결정론적 확정 (문서 파싱되면 verdict 닫힘, ~5)**: 대항력 · 전입일·확정일자(배당기준일) · 배당요구 유효성 · 보증금 인수 *범주* · 주택 소액임차인 최우선변제 O/X. + 말소기준 date 비교로 파생되는 선후판정(전세권·가처분·가등기·공유지분의 인수/소멸 방향).
- **B. 자동 탐지 + 보수 표기 (대부분)**: 특이사항을 자동 태깅하고 법령·판례 근거(briefing-rights)를 첨부하되, **성립·금액·확정은 `미확인`**. 확신 없으면 항상 인수·위험 쪽으로 보수 표기(false negative가 가장 위험).
- **C. 자동 불가 → 항상 미확인/N/A**: 경계 문제, 맹지/도로 접함, 명도비용 금액, 체납관리비 금액. 데이터 원천이 표준 문서셋에 없음.

### 항목별 완전자동 매핑

| 항목 | 방식 | 자동도 | 데이터 없을 때(무인 fallback) |
| --- | --- | --- | --- |
| 대항력 | 규칙엔진 | **완전** | 날짜 결측 시에만 미확인 |
| 전입일·확정일자 | 규칙엔진 | **완전** | 날짜 결측 시에만 미확인 |
| 배당요구 | 규칙엔진 | 부분 | 자료 결측→X/‘-’ (배당 가정 안 함) |
| 보증금 인수 | 규칙엔진 | 부분 | 범주 확정, 금액은 배당표 미완→미확인(상한=전액) |
| 선순위 전세권 | 규칙엔진 | 부분 | 배당요구 파싱 실패→인수위험(미확인) |
| 가처분 | 규칙엔진 | 부분 | 선순위=인수 확정, 후순위 예외는 미확인 |
| 가등기 | 규칙엔진 | 부분 | 성격 불명→소유권상실 위험(미확인) |
| 공유지분 매각 | 규칙엔진 | 부분 | 지분매각 확정, 우선매수 결과 N/A |
| 법정지상권 | 자동탐지 | 부분 | 탐지→토지인수 위험, 성립 미확인 |
| 유치권 | 자동탐지 | 부분 | 신고 탐지→인수 위험, 진위 미확인 |

| 점유자 미상/점유관계 | 자동탐지 | 부분 | 미상은 확정불가→‘미상’+점유자 존재 가정 |
| 위반건축물 | 자동탐지 | 부분 | 대장 미확보→미확인, 탐지→강제금 위험(금액 미확인) |

| 농지취득자격증명 | 자동탐지 | 부분 | 대상 태깅 확정, 발급 가능성 미확인 |
| 제시외 건물 | 자동탐지 | 부분 | 탐지→인수/철거 위험, 소유관계 미확인 |
| 재개발·재건축 | 자동탐지 | 부분 | 구역 태깅 확정, 조합원 지위 미확인 |
| 입찰보증금 특례 | 자동탐지 | 부분 | 공고 보증금율 판독, 20~30%→재매각 신호 |
| 토지 별도등기 | KB추론 | 부분 | 인수특약 파싱 실패→인수 가능(미확인) |
| 대지권 미등기 | KB추론 | 부분 | 감정 대지권 파싱 실패→부담 가능(미확인) |
| 소유자와의 관계 | KB추론 | 부분 | 가장임차 의심 정황(미확인), 무상거주 단정 금지 |
| 문서 간 불일치 | KB추론 | 부분 | 대조문서 결측→해당 교차검증 미확인 |
| 명도 난이도 | KB추론 | 부분 | 정성 등급 추정만, 정량 미확인 |

| 무잉여 | KB추론 | 부분 | 선순위채권·집행비용 파싱 실패→미확인 |
| 취하 가능성 | KB추론 | 부분 | 신호만, 실제 취하 N/A(미래사건) |
| 체납관리비 | KB추론 | 부분 | 법리 자동 서술, 금액 항상 미확인 |

| 매각불허가 사유 | KB추론 | 부분 | 특정 사유만 탐지, 통합판정 미확인 |
| 맹지/도로 접함 | 불가 | **불가** | 지적도/GIS 부재→항상 미확인 |

| 명도비용 | 불가 | **불가** | 정량 산정 불가→미확인(관행 범위 서술만) |

### 항상 미확인 (irreducible — 입력 원천 없음)

경계 · 맹지 · 체납관리비 금액 · 명도비용 금액 · 유치권 성립 진위 · 법정지상권 성립 · 공유자 우선매수 결과 · 취하 실제 발생 · 위반건축물 강제금 금액 · 농취증 발급 가능성 · 재개발 조합원 지위/분담금.

### 자동화 확대를 위한 보강 backlog (kbGaps, 우선순위)

1. **외부 문서 수집·파싱 파이프라인** (최대 레버) — 건축물대장·토지이용계획확인서·전입세대열람. operation-rules 게이트1의 자동 태깅 트리거가 이 텍스트 확보에 의존(위반건축물·재개발·농취증·대항력).
2. **무잉여 산식 코드화** — 용어사전 T009 공식 존재, 규칙엔진 미수록 + 우선변제채권액 자동 합산 규칙.
3. **부대비용 취득세율표·법무사보수·설정비 데이터** — 실질취득원가 공식 존재, 세율표만 보강하면 개산 자동.
4. **입찰보증금율 로직** (10%/재매각 20~30%) · **매각불허가 통합 카탈로그** · **가처분/중복병합 전용 규칙**.
5. **상가 환산보증금 기준표** — 현재 미구현 → 상가 최우선변제 자동 불가.
6. **지적도/GIS 접도 연동** — 맹지 판정(현재 불가).

### 무인 발급 법적 권고 (liability)

지식베이스 자체(`operation-rules.md`)가 **4-게이트(담당자 현장조사 + 검수인 크로스체크)를 발행 필수 전제**로 설계했고 돈 직결 항목은 이중 재계산을 강제한다. 인간 검수를 제거하면 이 방어 설계가 붕괴하므로:

1. **명칭 격하**: '보증서' → '**자동 권리분석 리포트(비보증)**'. 확정 문구는 결정론 5항목에 한정.
2. **B·C 항목**은 '위험 자동 태깅 + 법령·판례 근거 첨부'까지만, 성립·금액은 `미확인`. 확신 없으면 항상 위험 쪽 보수 표기.
3. 모든 산출물에 '**현장·관청 미검증, 최종 입찰 책임은 이용자**' 면책 + 판정 근거(파일·규칙·법령) 기록 → 사후 분쟁 방어.
4. **경계·맹지 등 데이터 없는 항목은 `N/A`로 명시** → 침묵에 의한 오인(부작위) 리스크 차단.

## 구현 현황 (2026-08-31)

- **HTML 렌더 완료** — `certificate.html`에 '특이사항 종합 체크표' 페이지 추가(32항목 색상 표 + 위험/확인필요 상세 전개 + 면책·판정근거). `render_certificate_template`에 `checklistRows`/`checklistDetails` 배선. 스모크 렌더 검증(플레이스홀더 치환·칩 생성).
- **PPTX 렌더 완료 (2026-09-07)** — 기존 1~3페이지를 유지하고 빈 4번째 슬라이드에 32항목 체크표를 2열로 렌더링하며, 위험·확인필요 항목은 근거자료와 함께 후속 슬라이드로 자동 분할한다. 따라서 PowerPoint PDF 변환본과 PPTX 폴백 모두 체크표를 포함한다.
- **정직성 설계** — 탐지 미구현 항목(제시외·재개발·점유미상·가장임차·현황변경·중복)은 '이상없음'이 아닌 `미확인`으로(거짓 음성 차단). 실행 결과 예: 아파트+가처분 선순위+유치권 신고 → 위험 2·확인필요 3·미확인 12·해당없음 3.
- **남은 단계** — ① 무잉여 산식 코드화(현재 미확인) ② 배당 시뮬레이션(보증금 인수 '금액') ③ 미구현 탐지 6종 추가로 미확인 축소.
- **도메인 튜닝 대기** — 부대비용 기본값(확인필요), 체납관리비 임계(>0) 등은 수치·기본값 조정 가능(캘린더 배율처럼).
- **검증 실행** — automation-service는 selenium/pptx 의존이라 전체 PDF 생성은 서비스 실행 필요. 코어·어댑터·렌더는 단위·스모크로 검증(전체 PDF 육안 확인은 서비스 기동 시).

## ⚠️ 자동판정 전제 (핵심 리스크)

`crawler.py`는 마이옥션 **물건상세 페이지(기본정보·감정평가현황·건축물현황)만** 파싱한다.
**등기부등본·매각물건명세서·현황조사서는 크롤러가 자동 수집하지 않는다.**
따라서 아래 auto/hybrid 판정 중 등기부·명세서·현황조사서에 의존하는 것(대항력, 배당요구, 인수/소멸, 전세권·가처분·가등기 등)은 **해당 문서가 업로드·OCR로 파이프라인에 공급될 때만** 실제로 동작한다. 운영에서 이 입력이 확보되는지 확인이 선행되어야 한다.

## 순서 근거

카테고리는 로드맵 4축(권리관계→임차·점유→물건 위험→입찰·비용)을 유지 — 권리분석 실무 순서(등기부 권리 확정 → 임차·점유 인수 판정 → 물건의 물리적/행정 위험 → 입찰 비용)와 일치. 카테고리 내부는 **인수·비용 위험의 영향도 + 자동판정 성숙도**를 함께 고려해, 인수 위험이 크고 자동 신호가 있는 항목을 앞, 데이터가 없어 수동 확인에 의존하는 항목을 뒤로 배치했다.

- 로드맵 대비 이동: 임차·점유에서 '전입일·확정일'을 앞(2번째)으로, '소유자와의 관계'를 뒤로. 물건 위험에서 자동 신호가 있는 hybrid를 앞, 탐지 룰 없는 manual(제시외·맹지·경계·재개발)을 뒤로.
- 로드맵 ②'보증금 인수' = ④'임차보증금 인수' 동일 개념 → 임차·점유 단일 항목으로 통합(중복 제거).

> 위 '확정 결정'에서 항목 노출 범위·상태 체계·상품명·입력 확보는 결정 완료. 아래는 남은 항목.

1. **보증금 인수 통합 승인**: ②·④ 단일 항목 통합 + 금액은 §3 비용요약에서만 표기 — 스펙 반영, 이의 없으면 확정.
2. **수동체크 UI·미입력 처리**: manual/hybrid 입력 UI 범위 + 미입력 시 '미확인' + `검토용 초안` 워터마크 적용 여부.
3. **상태 임계값**: 무잉여 소액 기준, 취하 70%, 체납관리비 고액, 명도비 고액 등 수치 임계 승인.
4. **hybrid 보수 표기**: '자동 신호 없음'을 '이상없음' vs '미발견(확인 권고)'로 보수적 표기.
5. **체납관리비 표기·면책**: 공용/전유/연체료 구분 + '전액 인수 아님' 면책 문구 법률 검토.
6. **상가 물건**: 환산보증금 룩업 미구현 상태에서 상가 대항력·최우선변제·인수 판정 방식.
