# 매수신청 대리 정보 및 Slack 알림

- 매출내역 추가에서 매수신청대리 선택 시 대리인(자유 텍스트, 최대 100자)과 대리일(날짜)이 필수다.
- 미정을 체크하면 빈 값으로 등록할 수 있다. 체크 시 경고 팝업, 저장 시 재확인을 제공한다. 입력된 일부 값은 보존한다.
- 상세 화면의 대리 정보 저장으로 추후 수정한다. 본인과 기존 회계 수정 권한자는 확정 매출에서도 대리 일정 정보만 수정할 수 있다. 금액/급여/승인 정보는 이 전용 API로 수정할 수 없다.
- 환불신청·환불완료 건은 대리 정보를 수정하지 못하며 알림에서도 제외한다.
- 기존 건은 미정으로 초기화되므로 과거 정보나 일정을 추정하지 않는다. 유형 변경 시 대리 정보를 초기화하여 이전 유형의 일정이 재사용되지 않는다.

## 발송 규칙

- 지출결의서와 동일한 `SLACK_EXPENSE_RECEIPT_WEBHOOK_URL`, 미설정 시 `SLACK_ACCOUNTING_WEBHOOK_URL`을 사용한다. 신규 채널 또는 개인 DM을 만들지 않는다.
- 한국시간 대리일 오후 14시부터 기존 30분 Cron이 조회한다. 주말도 대리일이면 포함한다.
- 오후 14시 이후 당일 건을 등록/확정하면 다음 Cron에서 발송한다. 날짜가 지난 건은 자동 소급 발송하지 않는다.
- 미정이 아니고 대리인·대리일이 기재된 매수신청대리 수입 중 pending/confirmed/card_pending 상태만 대상이다.
- 신청자=매출 담당자, 지사/부서=해당 매출의 지사/부서, 금액=proxy_cost(대리인 지급금액). 귀속 집계 지사로 바꾸지 않는다.
- 결재/확인 링크는 기존 로그인/조회 권한을 그대로 적용하며 해당 매출 월과 행을 지정한다. 별도의 결재 승인 기능을 추가하지 않는다.
- 매출 ID + 대리일 단위로 중복을 방지한다. 동일 날짜의 발송 완료 후 정보만 수정하면 다시 발송하지 않으며, 날짜 변경 시 새 날짜에 발송한다.
- 명시적 HTTP 실패는 다음 실행에서 재시도한다. 응답 불명확한 네트워크 오류는 `uncertain`, 발송 처리 중 중단은 `sending`으로 남겨 자동 중복 전송하지 않는다. Slack 수신 내역을 확인한 뒤 관리자가 재처리 여부를 결정해야 한다. 웹훅의 전달 보장/정확히 한 번 전송은 보장할 수 없다.
- 웹훅이 없으면 발송하지 않고 운영 로그에 설정 누락을 남긴다. 웹훅 주소는 로그에 출력하지 않는다.

## 데이터베이스

`ensureSalesProxySchema`가 API/Cron 최초 실행 시 추가 컬럼과 발송 기록 테이블을 보강한다. 수동 적용 SQL은 `d1/migrate-sales-proxy.sql`이며 ALTER 부분은 기존 컬럼이 없는 경우에만 한 번 적용한다.

- sales_records: proxy_agent, proxy_date, proxy_undecided
- sales_proxy_slack_deliveries: sales_id, proxy_date, status, updated_at

사용자 실데이터 수정이나 실제 Slack 발송은 테스트에 사용하지 않는다.

## 운영 수동 테스트

사용자가 명시적으로 요청한 경우에만 `POST /api/_test-slack-sales-proxy`로 합성 메시지 1건을 발송할 수 있다.
`SLACK_PROXY_TEST_TOKEN` 임시 시크릿과 일치하는 Authorization Bearer 헤더가 필요하며, 시크릿이 없으면 403으로 차단한다.
토큰 원문 대신 SHA-256 식별자를 `sales_proxy_slack_tests`에 기록하여 같은 키의 중복 발송을 막는다.
테스트는 실제 매출·정기 발송 기록을 만들지 않고 테스트 표시/가상 금액/업무성과 목록 링크를 사용한다.
발송 후 임시 시크릿을 삭제한다. 모호한 실패에 새 키를 만들어 재발송하기 전에는 Slack 수신 여부를 먼저 확인한다.
